# Informatica CS Job

**Section:** [[Job-Types-MOC]] · **Parent:** [[Data-Integration-Jobs]]

Informatica Cloud Services (CS) enable you to integrate and synchronize data, applications, and processes that are on-premises or in the cloud.

To create an Informatica CS job, see [[Creating-a-Job]]. For more information about this plug-in, see [[Control-M-for-Informatica-CS|Control-M for Informatica CS]]. The following table describes the Informatica Cloud Services job attributes.

| Attribute | Description |
|---|---|
| Connection Profile | Determines the authorization credentials that are used to connect Control-M to Informatica Cloud Services, as described in [[Informatica-CS-Connection-Profile-Parameters]].<br>Variable Name: %%INF-ACCOUNT |
| Task Type | Determines one of the following task types to execute on Informatica Cloud: • Mapping Task: A set of instructions that defines how data is transformed and moved from its source to its target system. • Masking Task: A data security technique that enables you to protect sensitive data while it allows it to be used for non- production purposes. • PowerCenter Task: A data integration tool that enables you to extract, transform, and load data from different sources into a unified target system. • Replication Task: A data replication solution that enables you to replicate and synchronize data across different systems and databases in real time. • Synchronization Task: A data integration solution that enables you to synchronize data between different systems and databases, which ensures that data is consistent and up-to-date across all systems. • Linear Taskflow: A workflow automation feature that enables you to create and automate a sequence of tasks that are executed in a specific order, which helps streamline data integration and processing tasks. • Taskflow: A workflow automation feature that enables you to create complex workflows that orchestrate and automate data integration and processing tasks across multiple systems and platforms. • Process: An Application Integration object to design and automate business workflows and service orchestration logic. It defines a series of steps to automate tasks such as to read data, make decisions, call APIs, or integrate with other systems. |
| Use Federation ID | Determines whether to identify the task using a Federated Task ID, which is a unique identifier that is used to track and manage tasks across distributed environments in a federated environment. This ID is generated by the Informatica domain and is important for monitoring and troubleshooting tasks.<br>This attribute is not required when you run a taskflow. |
| Task Name | Defines the name of the task that runs on Informatica Cloud.<br>This attribute is not required when you run a taskflow or use a Federated Task ID. |
| Folder Path | Defines the folder path of the task that runs on Informatica Cloud.<br>This attribute is required if you use a Federated Task ID. |
| TaskFlow URL | Defines the service URL of the taskflow that runs on Informatica Cloud.<br>You can find this URL if you click in the top, right corner of the TaskFlow main page of Informatica Data Integrator and click Properties Detail.... |
| Rerun Suspended Taskflow | Determines whether to re-execute a suspended taskflow. |
| Process Name | Defines the name of the process that runs on Informatica Cloud. |
| Input Fields | Defines input fields for a taskflow, in the following format:<br>input1=value1&input2=value2&input3=value3 |
| Call Back URL | ( Optional) Defines a publicly available URL where the job status is posted. |
| Rerun Run ID | Defines the Run ID to rerun a suspended taskflow.<br>The Run ID is unique to each job run and is available in the job output, next to the variable name RUN-UCM-RUNID. |
| Restart on Rerun | Determines whether to start from the point of failure in the pipeline when you rerun the job.<br>This parameter must always be disabled in the job definition in the Planning domain.<br>To activate this functionality, you must enable it in the Job Settings in the Monitoring domain before you rerun the failed job.<br>Default: Off |
| Status Polling Frequency | Determines the number of seconds to wait before checking the job status. |
